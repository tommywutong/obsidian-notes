# 2026 暑假 iOS 底层学习计划

> [!warning] 三个需要纠偏的原清单表述
> - **dyld2 / dyld3**：作为历史演进学习，同时补到 dyld4 和现代系统的 launch closure；不要把 dyld3 当成当前终点。
> - **GCD 线程池**：队列是任务组织与同步抽象，不等于线程；工作线程由系统调度管理。
> - **UITableView 必须实现的 delegate 方法**：`UITableViewDelegate` 没有“为了显示表格而必须实现”的方法；真正必需的是 `UITableViewDataSource` 的两个方法。

**本周目标**：能从“一个 Objective-C 对象在内存里是什么”一路讲到继承、元类、`isa`、Tagged Pointer、内存分区以及 ARC/MRC 的职责边界。

### 本周递进路线与精读顺序

#### Day 1｜先分清“地址空间”，不要一上来背 isa

- **为什么先学它**：后面说“对象在堆上”“类对象在数据区”“Tagged Pointer 不分配堆内存”时，都依赖这张内存地图。
- **A 必读**：R05 的 Apple Virtual Memory，只读虚拟地址空间、page、region 的概念；再读 `[[Mach-O]]`，观察 `__TEXT`、`__DATA` 与运行时内存区不是同一种分类。
- **B 精读**：暂不扩展更多博客。先把“源代码里的变量”“进程地址空间”“物理内存”三个层级分开。
- **实验**：分别声明局部变量、全局变量、静态变量、字符串字面量和 `NSObject`；在 LLDB 用 `p/x &variable`、`p/x object` 记录地址。
- **通过标准**：能解释“五大分区”是面试教学模型，不是每个对象都能机械塞进五个盒子。
- **卡住时**：只保留三类：可执行映像、栈、堆；其余细分等第七周 Mach-O 再补。

#### Day 2｜从一个对象逐层走到元类

- **A 必读**：`[[Runtime/Part 1 - 对象与类的本质]]` 的“对象的本质：objc_object”→“类的本质：objc_class”→“元类 metaclass”→“isa 走位与继承链”。第一次跳过 PAC 和所有源码宏展开。
- **A 官方**：R01 的 Programming with Objective-C，只读 Defining Classes 中 inheritance、class objects；WWDC20 只看 class data 与内存优化部分。
- **B 精读**：Always Processing 的 Class Architecture；读完自己重画，不复制文章图。
- **C 查证**：objc4 中只定位 `struct objc_object`、`struct objc_class`、`class_data_bits_t`，不追 `realizeClass`。
- **实验**：`object_getClass` 连续调用实例、类对象、元类；同时打印 `class_getSuperclass`。
- **通过标准**：闭卷画出实例 → 类 → 元类的 `isa`，以及类 → 父类、元类 → 父元类的 superclass。

#### Day 3｜在结构图上推导类型判断，再看 Tagged Pointer

- **前半段**：先用 Day 2 的两条链推导 `isKindOfClass:` 和 `isMemberOfClass:`，再读 Part 1 对应章节；不先背答案表。
- **后半段 A**：读 Part 1 的“Tagged Pointer 优化”和 R03 的 WWDC20；只掌握“不进行普通堆分配、值编码在指针中、布局随平台/版本变化”。
- **B 精读**：Always Processing Tagged Pointers，重点看“怎么识别”和“如何找到类”，不要背某一代掩码常量。
- **实验**：对短/长 `NSString`、小/大 `NSNumber` 打印地址、class、`malloc_size`；记录模拟器和真机结果可能不同。
- **通过标准**：能把类型判断结果推导出来；能解释 Tagged Pointer 的收益和不能背死的实现细节。

#### Day 4｜先用 MRC 学所有权规则，再看 ARC

- **A 必读**：R04 的 Apple Memory Management Guide，只读 Ownership Policy、Use Accessor Methods、Practical Memory Management；把 `new/copy/alloc/retain` 规则写成四行。
- **A 官方**：Clang ARC Specification 先读 General、Retainable Object Pointers、Ownership Qualification；先不读形式化转换细节。
- **实验**：建立一个关闭 ARC 的命令行 target，写 `retain/release/autorelease`；用 Zombies 验证过度释放。
- **输出**：同一段代码写 MRC 与 ARC 两版，标出“开发者删除了什么代码”和“所有权规则没有消失”。
- **通过标准**：能逐行判断谁拥有对象、所有权何时转移，而不是只会说“ARC 自动管理内存”。

#### Day 5｜把 ARC 拆成编译器与 runtime 两半

- **A 必读**：Clang ARC 的 Semantics；重点找 `objc_retain`、`objc_release`、`objc_storeStrong`、weak 相关 runtime calls。
- **B 精读**：Mike Ash ARC；关注编译器怎样根据所有权约定插入操作。
- **C 查证**：用 `clang -S -emit-llvm -fobjc-arc` 看 LLVM IR；只识别调用，不要求读懂全部 IR。
- **串联**：回看 Day 1 的地址图和 Day 2 的对象图，画出一个 strong 引用创建、赋值、离开作用域、dealloc 的全流程。
- **通过标准**：回答 ARC 做了什么时，必须分别说“编译期静态分析/插桩”和“运行期引用计数/弱引用表等支持”。

#### Day 6｜只收口，不增加新名词

- 闭卷重画三张图：地址空间、对象/类/元类、所有权生命周期。
- 重做 Day 2、Day 3 的 LLDB 实验，不看命令记录。
- 从本周验收题随机抽 5 题，每题先用 30 秒给结论，再展开 2 分钟。
- 产出一张“稳定语义 vs 当前实现”表：继承/所有权规则放左侧；nonpointer isa 位布局、Tagged Pointer 编码放右侧。
- 如果 5 题中有 2 题无法展开，先补对应 Day，不进入 weak。

### 本周验收题

- `id obj = [NSObject new]` 后，变量、指针、对象本体分别在哪里？
- 实例、类对象、元类之间的 `isa` 与 superclass 链怎么走？
- `isKindOfClass:` 为什么不能只背结果表，应该怎样沿继承关系推导？
- ARC 是垃圾回收吗？编译器做什么，Objective-C runtime 又做什么？
- Tagged Pointer 为什么能节省一次堆分配？哪些细节属于版本实现、不能背死？

## 第二周：weak、属性关键字与 Block

**本周目标**：把“语法糖”还原成所有权关系、编译器变换与运行时数据结构；能解释 weak 全流程和 Block 从字面量到调用的全过程。

| 日程 | 学习内容 | 对应原清单 | 当天产出 |
|---|---|---|---|
| Day 1 | `strong/copy/weak/assign/unsafe_unretained/atomic/nonatomic/readwrite/readonly`；深浅拷贝；`retain/release` | W2-07、W2-08、W2-09 | 一张属性关键字决策表；分别为 NSString、delegate、Block 选属性并解释 |
| Day 2 | weak 的引入、本质、SideTable/weak table、注册与读取流程、dealloc 置 nil | W2-01～W2-06 | 一张 `objc_storeWeak` → 注册 → 读取 → `clearDeallocating` 时序图 |
| Day 3 | Block 的 ABI、descriptor、invoke 指针；global / stack / malloc Block | W2-12、W2-13、W2-15 | 用 `clang -rewrite-objc` 对照一个无捕获和一个有捕获 Block |
| Day 4 | 自动变量、静态变量、对象、`__block` 的捕获；ARC 下复制与释放 | W2-10、W2-11 | 四种捕获实验 + 捕获前后内存图 |
| Day 5 | Block 循环引用、weak-strong dance、生命周期；Block 判空规范 | W2-14、W2-16 | 修复 3 个循环引用例子；写出安全调用模板并解释何时仍有竞态 |
| Day 6 | 综合实验与模拟面试 | W2-01～W2-16 | 手写简化 Block 结构体；15 分钟无稿讲解 weak + Block |

### 本周递进路线与精读顺序

#### Day 1｜先把属性翻译成所有权关系

- **前置回忆**：用第一周的 ownership rules 判断 strong、copy、weak 分别想表达什么，再看语法。
- **A 必读**：R07 的 Encapsulating Data，只读 property attributes、synthesized accessors；NSCopying 只看 `copyWithZone:` 契约。
- **实验顺序**：`NSString` 的 strong/copy → `NSMutableString` 的 strong/copy → delegate 的 strong/weak → Block 的 strong/copy。
- **输出**：属性表必须包含“setter 大致语义、适合对象、风险、是否涉及线程安全”；`atomic` 不得写成“线程安全”。
- **通过标准**：给出一个属性声明时，能从业务所有权推导关键字，而不是从类型名字猜。

#### Day 2｜weak 按“写入—读取—销毁”三段学

- **A 必读**：Clang ARC 先看 weak 语义；再读 R06 的 objc4 源码入口说明。
- **C 源码只追一条线**：`objc_storeWeak` → `storeWeak` → `weak_register_no_lock`；销毁侧找 `clearDeallocating` → `weak_clear_no_lock`。
- **数据结构**：先明确 `SideTable`、`weak_table_t`、`weak_entry_t` 的包含关系，再看哈希细节。
- **实验**：给对象加 weak 引用，在 `dealloc` 前后打印；再用 `__unsafe_unretained` 对照悬垂指针风险。
- **通过标准**：能从“为什么需要 weak”讲到“对象销毁时怎样找到并清空所有弱引用槽位”。
- **卡住时**：先只记“全局分片表 + 被引用对象到弱引用地址集合”，暂不追 inline/out-of-line entry 优化。

#### Day 3｜先看 Block 是什么，再谈捕获

- **A 必读**：Apple Blocks Introduction；Clang Block ABI 只读 Block Implementation Specification 的结构体字段。
- **实验**：无捕获 Block、捕获自动变量 Block、全局 Block 各跑一次 `clang -rewrite-objc`。
- **观察点**：`isa`、flags、invoke、descriptor 分别承担什么；调用 Block 本质上怎样走到 invoke 函数。
- **B 精读**：Mike Ash Blocks，用来补 ABI 图景，不要求记历史编译器差异。
- **通过标准**：能画出简化 Block 结构体并说明 `block(args)` 到 invoke 的路径。

#### Day 4｜在结构体基础上研究捕获与复制

- **A 必读**：Apple Blocks and Variables，按自动变量、静态变量、全局变量、`__block` 顺序阅读。
- **实验矩阵**：值类型/对象 × 有无 `__block`；每组记录捕获方式和变量修改是否可见。
- **所有权串联**：把 Block 从栈语义复制到堆后，说明捕获对象与 `__block` forwarding 的生命周期变化。
- **输出**：不要只写“值捕获/引用捕获”；必须画出变量存储位置和谁持有谁。
- **通过标准**：给一段 Block 代码，能在运行前判断打印值和潜在持有关系。

#### Day 5｜循环引用是 Day 4 所有权图的推论

- **顺序**：先独立画对象 → Block → 对象的环，再看 weak-strong dance，不直接背模板。
- **A 必读**：Apple Working with Blocks 的 avoid strong reference cycles；再读原清单简书文章作为中文辅助。
- **实验**：成员属性 Block、自持有 completion、timer/source 回调各做一个泄漏；用 Memory Graph 验证修复。
- **Block 判空**：说明 Objective-C 调 nil 方法安全，但调用空 Block 函数指针不安全；再讨论读取属性与调用之间可能发生的并发变化。
- **通过标准**：能区分“临时强持有保证回调期间对象活着”和“重新形成永久引用环”。

#### Day 6｜把 weak 与 Block 合成一张生命周期图

- 闭卷从 `self` 创建 Block 开始，画捕获、copy、回调、释放和 weak 清零。
- 分别回答“weak 的底层”和“Block 的底层”，然后用一道循环引用题把两者串起来。
- 重跑 `clang -rewrite-objc` 和 weak 置 nil 实验；命令可以查，结果必须先预测。
- 通过条件：16 个原条目能各用一句话定位到这张总图中的一个节点。

## 第三周：Runtime 行为与 Cocoa 对象通信

- **A 权威**：SQLite Language 只练 CRUD；Transactions 读 begin/commit/rollback；File Format 只看 page 与 B-tree page。
- **B 中文**：小林 MySQL 文章只辅助理解 ACID、隔离和 B+ 树，不把 MySQL 特有实现直接套到 SQLite/Core Data。
- **实验**：建立一张表，完成增删改查；开启事务后回滚；模拟唯一约束失败。
- **通过标准**：能用一句话解释 ACID；能说明 B+ 树减少磁盘 I/O 的直觉，不要求手写数据库。

#### Day 3｜序列化先比较需求，再看二进制细节

- **A 标准**：RFC 8259 只看 JSON 数据模型；W3C XML 了解 element/attribute；Protobuf Encoding 读 field number、wire type、varint、length-delimited。
- **实验**：同一 User 模型编码成 JSON/XML/Protobuf，比较 schema、可读性、兼容性、体积和调试体验。
- **深入顺序**：先手算正整数 varint，再学 ZigZag；不一开始背全部 wire type。
- **通过标准**：能根据跨语言、schema、演进、体积和可读性做选择，不回答“Protobuf 永远更快”。

#### Day 4｜JSONModel 只追一条主链

- **入口**：从 README 的最小使用例开始，找到模型初始化/转换入口。
- **旧知识回收**：第三周 Runtime API、KVC、属性列表与类型编码；不懂的先回旧笔记，不在源码中猜。
- **调用链模板**：公开 API → 属性元数据构建 → JSON key 查找 → 类型转换 → KVC/setter 赋值 → 错误处理。
- **输出**：每个节点写“输入、输出、缓存了什么”；第一遍不追所有 transformer 和 protocol hook。
- **通过标准**：可以从一次实际转换走完整链，并指出哪些位置依赖 KVC/Runtime。

#### Day 5｜用同一组问题读 YYModel，才有可比性

- **入口**：用与 Day 4 相同的 User 模型和 JSON，找到 YYModel 的入口。
- **比较维度**：类/属性元信息表示、缓存位置、类型转换、容器泛型、线程同步、错误/容错策略。
- **C 查证**：只追与比较表直接相关的函数；不要因为 YYModel 更复杂就逐文件阅读。
- **通过标准**：能说出两个库的设计差异和权衡，而不是只说“YYModel 性能更好”。

#### Day 6｜SDWebImage 第一遍只看成功路径

- **入口**：从 UIImageView category 的设置图片 API 开始，追到 manager、cache query、downloader、completion。
- **旧知识回收**：Block 生命周期、GCD 回调、URL Loading、UITableView cell reuse。
- **图示**：缓存命中与未命中两条路径；标出回调在哪个队列、何时回主线程更新 UI。
- **通过标准**：能在不看源码的情况下复述一次成功请求的主流程。

#### Day 7｜第二遍才看性能与取消

- **问题驱动**：相同 URL 如何合并请求？cell 复用时如何取消？图片在哪一步解码？内存/磁盘缓存 key 如何形成？
- **实验**：快速滚动列表并记录重复请求、取消、缓存命中和解码热点。
- **串联**：回到第六周 baseline，说明 SDWebImage 解决了哪些问题、哪些布局/主线程问题仍由业务负责。
- **通过标准**：画出包含 pending/running/cancelled/completed/cache-hit 的简化状态机。

#### Day 8｜架构是前七天代码的职责重排

- **A 官方**：Cocoa MVC 的 model/view/controller roles；再读 objc.io MVVM。
- **实践**：用 Day 6～7 的图片列表页，先标出网络、转换、缓存、展示、交互，再分别放入 MVC/MVVM。
- **双向绑定**：明确 View→ViewModel 和 ViewModel→View 的触发、去重、线程和生命周期；不用“自动同步”四字带过。
- **通过标准**：架构选择必须能回答可测试性、依赖方向、状态所有者和页面复杂度。

#### Day 9｜网络基础放到 URLSession 下面分层

- **A 顺序**：先应用层 HTTP/HTTPS，再传输层 TCP/UDP，最后网络层 IP；遵循原清单“只看上三层”。
- **权威资料**：URL Loading System 建立 iOS 入口；RFC 9110/9293 用来查语义；小林 coding 用图辅助。
- **输出**：HTTP 解决消息语义，TCP/UDP 解决端到端传输，IP 解决寻址与路由；每层先写一句话。
- **通过标准**：能从输入 URL 讲到 DNS、连接/TLS、HTTP、响应数据；不需要扩到链路层细节。

#### Day 10｜用一个小项目证明知识连接起来了

- **最小需求**：URLSession 拉 JSON → JSONModel 或 YYModel 转模型 → SDWebImage 展示图片 → 缓存/持久化一项数据 → UITableView 展示。
- **必须留证**：一次网络 trace、一次模型转换调用链、一次图片缓存命中、一次列表性能采样。
- **架构复盘**：标出每层职责和所有权；指出至少一个可替换点，例如模型库或缓存实现。
- **最终口述**：从“用户打开页面”讲到“像素上屏”，串联 dyld/启动、网络、模型、缓存、主线程、RunLoop 与渲染。
- **通过标准**：10 分钟内主线完整、关键边界准确；细节不会时能指出资料和源码入口。
